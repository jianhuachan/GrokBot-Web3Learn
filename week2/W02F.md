# W02F：第 2 周 Review

## 连接钱包的疑惑

### 疑问 1
**Kian：** 连接钱包时 MetaMask 添加的是本地 URL，为什么说是本地页面向钱包请求账户地址？

**回答：** 添加自定义网络只是让页面能跟本地 Hardhat 链通信（余额、交易都走这条链）。页面显示你的地址，靠的是另一步：连接授权（`eth_requestAccounts`）。没点“连接”，页面不知道你是谁。

### 疑问 2
**Kian：** 是不是因为在 MetaMask 里添加了自定义 network，localhost 才显示 Account 1 地址？

**回答：** 不是。自定义网络决定“连哪条链”，地址显示决定于“有没有授权连接”。页面通过浏览器插件注入的 `window.ethereum` 调用 `eth_requestAccounts`，MetaMask 弹出授权框，你点同意后才把地址列表返回给页面。

### 疑问 3
**Kian：** 如果浏览器没有 MetaMask 插件，页面怎么知道钱包地址？

**回答：** 没有 MetaMask 插件就没有 `window.ethereum`，连接会失败，页面拿不到地址。除非装了 Rabby、Coinbase Wallet 等能注入同样接口的钱包扩展。

## 停止 RPC 的疑问

**Kian：** 第三点，异常检查，停止RPC的现象不只是浏览器没有信息，前端会连接不上节点，余额读不出来，页面报错，MetaMask发交易也会失败。我怎么样停止RPC啊？

**回答：** 最直接的是在跑 `yarn chain` 的 Hardhat 终端按 `Ctrl+C`，链和 RPC 就一起停了；或者直接关掉那个终端窗口也行。

## Review 脚本：我的回答与纠正

### 第 1 点：连接钱包、消息签名、发送交易有什么不同？读取合约一定需要钱包吗？

**Kian：**
连接钱包 - MetaMask 选择network 添加自定义network, 连接本地HardHat
消息签名 - 修改block 的信息需要确认就需要签名
发送交易 - 如需转账 钱包send 填写to 的地址,确认后会有transaction id
读取合约不一定需要钱包, 可以在eth 搜索transaction

**纠正：**
- **连接钱包**：添加本地网络只是准备工作。连接的本质是网页向钱包请求账户地址（`eth_requestAccounts`），你同意后网页才知道你是谁；不签名、不花钱。
- **消息签名**：写反了。签消息是在链下证明“这个地址是我的”（例如用钱包登录网站），**不改链上数据、不上区块、没有 gas**。
- **发送交易**：要改链上状态（转账、改 greeting）才发交易，需要签名、付 gas，返回 transaction hash。
- **读取合约**：结论对，不需要钱包。但方式是通过 RPC 做 `eth_call` 直接读（如 Debug 页读 greeting），不是“搜索 transaction”，查交易是另一回事。

### 第 2 点：从停止状态启动已有本地环境，连接正确网络，完成转账并定位回执

**Kian：**
scaffold yarn chain, yarn deploy, yarn start 之后 确认本地页面正常, 通过faucet 发起转账, 最后到Block Explore 查看该转账回执

**纠正：**
- 流程对。补充：转账前先确认 MetaMask 在 Localhost 31337 上。
- 回执里要看 **status 1**（对应 `eth_getTransactionReceipt`）。这正是门槛 G1 的重点：有交易哈希 ≠ 执行成功，status 1 才算成功。

### 第 3 点：取消一次请求；停止 RPC 服务，描述用户会看到什么，并恢复服务

**Kian：**
取消交易, 停止RPC, Block Explore 里不会有任何信息, 取消的交易不会上链, 可以通过yarn chain, yarn deploy, yarn start  恢复

**纠正：**
- 取消交易说对了：签名前拒绝，不会广播，也不会上链。
- 停止 RPC 的现象不只是浏览器没信息：前端会连不上节点、余额读不出来、页面报错，MetaMask 发交易也会失败。
- 恢复要注意：重启 `yarn chain` 后是全新的链，之前的合约、余额、交易都没了，必须重新 `yarn deploy`，MetaMask 可能还要重置账户（nonce）。

## 恢复失败的具体报错

**报错原文：**

```
RPC 0x7a69 Custom
eth_sendRawTransaction: Nonce too high. Expected nonce to be 0 but got 3. Note that transactions can't be queued when automining.
```

**场景：** 重启本地链后，在 Debug Contracts 页调用 `setGreeting`（`_newGreeting` = "sadfas"，payable value = 11 wei），点 Send 时报错。页面上 greeting 已变回默认的 "Building Unstoppable Apps!!!"，totalCounter 为 0。

**原因：** 重启本地链后，新链上该账户的 nonce 从 0 重新开始，但 MetaMask 还记着旧链上用过的 nonce，按 3 发送；节点期望 0，所以拒绝。

**处理：** MetaMask → 设置 → 高级 → **清除活动和 nonce 数据**（旧版叫“重置账户”）。只清 MetaMask 本地记录，不影响账户和私钥。清完刷新页面，再点 Send。

## 消息签名与停止 RPC

1. **连接钱包的三步**：页面通过浏览器插件注入的 `window.ethereum` 调用 `eth_requestAccounts` → MetaMask 弹出授权框 → 点同意后返回地址列表。（详见上文「连接钱包的疑惑」）
2. **消息签名是身份验证**：用私钥签一段文字，证明你控制这个地址，网站验证签名即可，不上链、不花 gas。常见场景：钱包登录、NFT 市场挂单、授权 DApp 代付 gas、链上身份绑定。
3. **停止 RPC**：在跑 `yarn chain` 的 Hardhat 终端按 `Ctrl+C`，或直接关闭那个终端窗口。（详见上文「停止 RPC 的疑问」）
